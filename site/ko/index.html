AgentMesh Deploy제품 출시를, 경계가 분명한 운영 Agent에게.

개발을 마친 Git 저장소를 넘기면 Commit을 고정하고 기술 스택과 공급자 전략을 분석해 실행 계획을 제시합니다. 비용, 데이터베이스 마이그레이션, DNS, 프로덕션 전환은 사용자가 승인하기 전에는 실행하지 않습니다. 제품 저장소는 기본적으로 읽기 전용입니다.

Agent에게 붙여넣기 · 운영 인계
https://github.com/jiyangnan/AgentMesh-Deploy-Agent 를 읽고 AgentMesh Deploy 최신 안정 버전을 설치한 뒤, 독립 운영 Agent로서 이 제품의 출시를 인계하세요.

먼저 저장소를 읽기 전용으로 분석하고 현재 Git Commit을 고정하세요. 제품 저장소의 Remote, Index, 작업 트리, 기록이나 기존 인증, 계정, 권한, 세션 체계를 수정하지 마세요.

권장 공급자 경로, 예산, 필요한 자격 증명, DB 마이그레이션, DNS / Resend, 롤백 계획을 제출하세요. 비용, 공급자 Mutation, DB 쓰기, DNS 변경, 실제 메일, 프로덕션 전환, 삭제 전에는 반드시 나의 명시적 승인을 요청하세요.
필요한 이유

개발 완료가 곧 출시 완료는 아닙니다.

도메인, 서버, 데이터베이스, 이메일, 환경 변수, CI/CD, 마이그레이션, 상태 확인, 롤백은 여러 공급자 화면에 흩어져 있습니다. AgentMesh Deploy는 이를 검토하고 승인하고 복구할 수 있는 하나의 출시 흐름으로 만듭니다.

독립 제어 평면

하나의 Deploy Agent가 여러 제품을 담당합니다.

제품 저장소에 Sidecar를 쓰지 않습니다. 고정된 Commit에서 격리 Checkout을 만들고 Manifest, Plan, Approval, Evidence, Run을 외부 Control Home에 저장합니다. 코드 변경이 필요하면 Patch 제안만 생성합니다.

제품 저장소는 읽기 전용 입력이며 공급자 변경은 계획, 승인, 증거 단계를 거칩니다.

핵심 기능

코드 스냅샷에서 검증된 온라인 결과까지.

모든 단계를 같은 Commit, Graph, 계획 지문에 연결합니다. 실패 시 공급자 사실을 먼저 대조한 뒤 Resume 또는 사람에게 인계를 선택합니다.

01 / SOURCE

읽기 전용 분석

격리 Checkout에서 프레임워크, 빌드, 환경 요구사항을 식별하며 작업 트리, Remote, 기록을 변경하지 않습니다.

02 / PLAN

결정적 공급자 계획

Launch Configuration으로 런타임, 데이터베이스, DNS, 이메일 Adapter Plan을 생성합니다.

03 / APPROVAL

권한과 예산 게이트

네트워크, Mutation, 비용, 마이그레이션, 프로덕션 전환을 따로 승인합니다. 정확한 Approval이 없으면 API 호출 전에 멈춥니다.

04 / DATABASE

마이그레이션 전 증거

Schema와 SQL 위험을 확인하고 Snapshot 또는 Backup Evidence를 만든 뒤 대상 버전 마이그레이션을 실행합니다.

05 / EDGE

DNS와 이메일

정확한 DNS Change Set으로 사이트와 Resend 도메인을 구성하며 모호한 조건으로 기존 레코드를 덮어쓰지 않습니다.

06 / RECOVERY

중단 후 복구

Intent를 먼저, Receipt를 나중에 기록합니다. 재개 시 이미 생성된 리소스를 대조해 중복 생성과 비용을 막습니다.

공급자 어댑터

하나의 흐름으로 핵심 여섯 공급자를 연결합니다.

v0.2.1은 여섯 핵심 Adapter 계약을 공개합니다. 자격 증명은 Secret Ref로만 사용하며 Token과 연결 문자열은 Plan, Run, State, 로그에 저장하지 않습니다.

사람과 Agent의 경계

Agent가 흐름을 실행하고 사람이 최종 권한을 가집니다.

사람은 책임이 필요한 결정에 집중하고 반복적이며 오류가 잦은 여러 플랫폼 작업은 Agent가 수행합니다.

Agent 자동 수행

발견과 계획

저장소를 분석하고 아키텍처 선택지, 예상 리소스, 변경 횟수를 제시합니다.

사람이 확인

계정과 자격 증명

가입, 신원 확인, 결제, 최소 권한 Token 생성과 Secret Backend 사용을 결정합니다.

Agent 자동 수행

후보 환경과 검증

격리 프로젝트를 만들고 고정 Commit을 배포해 HTTPS, API, DB, 이메일 상태를 확인합니다.

사람이 확인

비용과 데이터 위험

유료 요금제, 도메인 구매, 마이그레이션, 복구, 기존 데이터에 영향을 줄 수 있는 작업을 승인합니다.

Agent 자동 수행

증거와 Resume

불변 Receipt, 드리프트 감지, 불확실한 쓰기 대조, 정확한 복구 절차를 남깁니다.

사람이 확인

프로덕션 전환과 삭제

공식 DNS, 실제 이메일 발송, 프로덕션 트래픽, 리소스 삭제, 파괴적 DB 작업을 승인합니다.

첫 출시 흐름

개발 Agent에서 운영 Agent로 인계합니다.

CLI는 구조화된 nextActions를 반환합니다. 다음 Agent는 여섯 관리 화면에서 다음 단계를 추측할 필요가 없습니다.

01

제품 등록

로컬 또는 원격 Git을 제공하고 변경 불가능한 Commit을 고정합니다.

02

분석과 전략 선택

기술 요구사항을 식별하고 사람이 공급자 구성과 예산을 확인합니다.

03

제한된 자격 증명

최소 권한 Token을 Keychain, 1Password 등에 저장하고 참조만 등록합니다.

04

후보 환경 배포

Sandbox, Approval, Preflight 후 격리 리소스를 만들고 검증합니다.

05

프로덕션 전환 승인

DB, DNS, 이메일, 복구 증거를 확인하고 명시적 승인 후에만 변경합니다.

자주 묻는 질문

FAQ.

제품 저장소에 파일을 쓰나요?
V2는 기본적으로 쓰지 않습니다. 상태는 외부 Control Home에 저장하며 코드 변경이 필요하면 독립된 Patch 제안만 만듭니다.
AgentMesh360 계정이 필요한가요?
필요하지 않습니다. Apache 2.0 오픈소스 CLI입니다. 대상 공급자 계정과 최소 권한 자격 증명은 필요합니다.
도메인 구매나 프로덕션 전환도 자동인가요?
계획과 안내는 가능하지만 기본 실행하지 않습니다. 구매, 비용, DB 위험, 공식 DNS, 이메일 발송, 프로덕션 전환, 삭제에는 별도 승인이 필요합니다.
자격 증명은 어디에 저장하나요?
영구 객체에는 keychain://, op://, secret:// 같은 Secret Ref만 저장합니다.
중단되면 리소스가 중복 생성되나요?
Mutation은 Intent 이후 Receipt를 기록합니다. Resume은 공급자 사실을 먼저 대조하고 리소스 부재와 예산을 확인한 뒤 다시 실행합니다.
