必要な理由

開発完了は、公開完了ではありません。

ドメイン、サーバー、データベース、メール、環境変数、CI/CD、移行、ヘルスチェック、ロールバックは複数の管理画面に分散しています。AgentMesh Deploy は、それらをレビュー、承認、復旧できる一本のリリースフローにします。

独立コントロールプレーン

一つの Deploy Agent が、複数の製品を担当。

製品リポジトリへ Sidecar を書き込みません。固定した Commit から隔離 Checkout を作り、Manifest、Plan、Approval、Evidence、Run は外部 Control Home に保存します。コード変更が必要な場合は Patch 案だけを生成します。

製品リポジトリは読み取り専用の入力。プロバイダー変更は計画、承認、証跡を通過します。

中核機能

コードスナップショットから、検証済みの公開結果まで。

すべての段階を同一 Commit、Graph、計画フィンガープリントに結び付けます。障害時はプロバイダー上の事実を照合してから Resume または人への引き継ぎを選びます。

01 / SOURCE

読み取り専用の解析

隔離 Checkout でフレームワーク、ビルド、環境要件を検出し、作業ツリー、Remote、履歴を変更しません。

02 / PLAN

決定的な計画

Launch Configuration から、ランタイム、データベース、DNS、メールの Adapter Plan を生成します。

03 / APPROVAL

権限と予算のゲート

ネットワーク、Mutation、費用、移行、本番切り替えを別々に承認します。適合しない Approval では API 呼び出し前に停止します。

04 / DATABASE

移行前の証跡

Schema を確認し、SQL を分類し、Snapshot または Backup Evidence を作成してから移行します。

05 / EDGE

DNS とメール

正確な DNS Change Set でサイトと Resend ドメインを構成し、既存レコードを曖昧な条件で上書きしません。

06 / RECOVERY

中断からの復旧

Intent を先に、Receipt を後に記録。再開時に既存リソースを照合し、重複作成と重複課金を防ぎます。

人と Agent の境界

Agent が流れを進め、人が最終権限を持つ。

人は責任を伴う判断に集中し、反復的でエラーの起きやすいクロスプラットフォーム作業を Agent が担当します。

Agent が実行

発見と計画

リポジトリを分析し、構成案、必要リソース、変更回数を提示します。

人が確認

アカウントと認証情報

登録、本人確認、支払い、最小権限 Token の作成と保管先を決定します。

Agent が実行

候補環境と検証

隔離リソースを作成し、固定 Commit をデプロイして HTTPS、API、DB、メール状態を確認します。

人が確認

費用とデータリスク

有料プラン、ドメイン購入、移行、復旧、既存データへ影響する操作を承認します。

Agent が実行

証跡と Resume

不変 Receipt、ドリフト検出、未確定書き込みの照合、復旧手順を残します。

人が確認

本番切り替えと削除

正式 DNS、実メール送信、本番トラフィック、削除、破壊的 DB 操作を承認します。

初回リリース

開発 Agent から、運用 Agent へ引き継ぐ。

CLI は構造化された nextActions を返します。次の Agent は六つの管理画面で手探りする必要がありません。

01

製品を登録

ローカルまたはリモート Git を指定し、変更不能な Commit を固定します。

02

分析と方針選択

技術要件を検出し、プロバイダー構成と予算を人が確認します。

03

限定認証情報

最小権限 Token を Keychain、1Password などへ保存し、参照だけを登録します。

04

候補環境をデプロイ

Sandbox、Approval、Preflight 後に隔離リソースを作成して検証します。

05

本番切り替えを承認

DB、DNS、メール、復旧証跡を確認し、明示承認後だけ本番変更を実行します。

よくある質問

FAQ.

製品リポジトリへファイルを書き込みますか？
V2 は原則書き込みません。状態は外部 Control Home に保存し、コード変更が必要な場合は独立した Patch 案を作成します。
AgentMesh360 アカウントは必要ですか？
不要です。Apache 2.0 のオープンソース CLI です。対象プロバイダーのアカウントと最小権限の認証情報は必要です。
ドメイン購入や本番切り替えも自動ですか？
計画と案内はできますが、既定では実行しません。購入、課金、DB リスク、正式 DNS、メール送信、本番切り替え、削除には個別の承認が必要です。
認証情報はどこへ保存しますか？
永続オブジェクトには keychain://、op://、secret:// などの Secret Ref だけを保存します。
中断時にリソースが重複しませんか？
Intent の後に Receipt を記録します。Resume はプロバイダー上の事実を先に照合し、存在と予算を確認してから再実行します。
